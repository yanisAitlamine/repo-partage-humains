# Reprise courte du projet — 30 octobre 2026

La mission humaine courante fixe le périmètre. La documentation technique actuelle concerne Atelier Rust ; les anciens parcours n8n sont historiques. Le lab permanent contient la version applicative 4162a4f. La campagne de staging est une instance temporaire distincte, dont le résultat final appartient à son rapport.

## Commencer

Lire les consignes applicables, la référence de coordination partagée et le registre privé des environnements, puis les annonces récentes. Vérifier la version installée, les travaux réservés et l’état Git avant écriture. Ouvrir ensuite seulement les documents nécessaires à la mission.

Le Pi assure le VPN, le DNS et le proxy des sites de test. Le lab possède son propre HTTPS. La production applicative reste distincte sur le serveur de production. Les anciennes applications Atelier/n8n et l’Observatoire du Pi ont été retirés ; les anciennes procédures ne sont pas des commandes de réinstallation courantes.

## Règles de reprise

Source Git, version compilée, release installée et recette réussie sont des états distincts. La référence conserve le scénario restaurant réussi et les 29 scénarios à rejouer ensemble après correction du produit. Ne pas attribuer à la nouvelle campagne les résultats d’une ancienne.

Préserver les projets et sites existants, les travaux concurrents, les profils d’authentification et les preuves d’effets incertains. Une opération d’administration demande son périmètre humain ; la documentation ne l’autorise pas à elle seule. L’accès à la VM Kali personnelle reste soumis à une instruction la visant. L’outil personnel PIAgentControl reste réservé à Yanis.

Conserver les références d’accès et les détails d’exploitation dans la documentation privée. Terminer par les contrôles réellement exécutés, les limites concrètes, le nettoyage de ses temporaires et la libération des réservations. Les rapports datés conservent leur historique ; les guides courants remplacent les faits devenus faux.
